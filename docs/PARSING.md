# Парсинг

| Формат | Структура и координаты |
| --- | --- |
| PDF | Docling распознаёт порядок чтения и блоки. Структуру таблиц выделяет TableFormer в режиме FAST. PyMuPDF обеспечивает метаданные и резервное извлечение с физическими страницами. |
| DOCX | python-docx извлекает абзацы и таблицы в исходном порядке, заголовки, списки, подписи, гиперссылки и свойства. |
| DOC | LibreOffice headless преобразует бинарный файл в DOCX. Далее применяется общий Word-парсер. |
| TXT | Текст, абзацы, исходная кодировка, символьные диапазоны и строки. |
| Markdown | markdown-it-py обрабатывает строки, заголовки, списки, таблицы, цитаты, ссылки, код и математические обозначения в тексте. |
| HTML | BeautifulSoup и lxml извлекают блоки, metadata, структурные идентификаторы, ссылки, таблицы и подписи. |

Для PDF без извлекаемого текста используется статус `requires_ocr`. Включение OCR требует настроенного Docling, локальных артефактов и Tesseract CLI с языками rus и eng. Для Word viewer имеет PDF-копию при доступном LibreOffice. Ссылки ведут к разделу и абзацу, если отсутствует установленное соответствие страниц.

Для текстовых форматов поддерживаются UTF-8, UTF-8 BOM, UTF-16, Windows-1251, Windows-1252 и KOI8-R. При неоднозначности выберите кодировку при повторной обработке. Ошибки декодирования сохраняются как диагностика.

Пользовательские HTML и Markdown отображаются как данные. HTML preview строится заново из экранированных блоков. Переходы привязаны к заголовку, строкам, физической странице или блоку канонического представления.

Документация [Docling pipelines](https://docling-project.github.io/docling/reference/pipeline_options/) и [python-docx](https://python-docx.readthedocs.io/).
